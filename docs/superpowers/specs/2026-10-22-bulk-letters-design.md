# ออกร่างหนังสือหลายคนทีเดียว + อัปโหลดฉบับลงนามหลายฉบับ (หน้า T000)

วันที่: 2026-10-22 · ผู้ใช้: เจ้าหน้าที่ (ออกหนังสือได้เฉพาะเจ้าหน้าที่ — `lettersStaffOnly`)

## ทำไม

หลังอาจารย์/เจ้าหน้าที่ตรวจเอกสาร T000 ผ่าน ต้องออกหนังสือขอความอนุเคราะห์ให้นักศึกษา**ทุกคนในรอบแทบพร้อมกัน** (และหนังสือส่งตัวหลังตรวจใบตอบรับ)
ตอนนี้ต้องเปิดหน้าต่างออกหนังสือทีละคน → สร้างร่าง → โหลดทีละไฟล์ → เอาไปเสนอลงนาม → สแกน → กลับมาเปิดทีละคนเพื่ออัปโหลดฉบับลงนาม — เสียเวลามาก

ต้องการ: **โหลดร่างหลายฉบับครั้งเดียว** ไปเสนอคณบดีลงนาม แล้ว**อัปโหลดฉบับลงนามกลับหลายฉบับครั้งเดียว**

## สิ่งที่รู้จากการใช้งานจริง (ผู้ใช้บอก / ตัวอย่างหนังสือ 811 · 893 · 1215)

- เลขหนังสือราชการ (`ที่ อว 660301.26.6.2/<เลข>`) **เจ้าหน้าที่ออกให้ทีละฉบับ ตอนเตรียมไปเสนอลงนาม** · ใช้**ทะเบียนเลขชุดเดียวกันทุกประเภท** (811 ขอความอนุเคราะห์ → 893 ส่งตัว → 1215 ขอนิเทศ ไล่ตามเวลา) · ออกพร้อมกันหลายฉบับ = **เลขต่อกัน**
- นักศึกษาบริษัทเดียวกัน**ส่วนใหญ่รวมเป็นหนังสือฉบับเดียว เลขเดียว** (ตัวอย่าง 1215: 2 คน) — มีบ้างที่แยก
- **Word สำคัญที่สุด** — เจ้าหน้าที่เอาไปแก้ให้ตรงรูปแบบหนังสือราชการก่อนพิมพ์ (PDF ที่ระบบสร้างยังไม่ตรงรูปแบบนัก) · PDF เป็นตัวเลือกรอง
- คณบดีลงนามบนกระดาษ (ไม่มีรูปลายเซ็นในระบบแล้ว)
- ฉบับลงนามสแกนกลับมา **ไฟล์แยกฉบับละไฟล์** · เจ้าหน้าที่ตั้งชื่อไฟล์ขึ้นต้นด้วยเลขหนังสืออยู่แล้ว เช่น `811-บริษัท แอดวานซ์ อินโฟร์ เซอร์วิส จำกัด (มหาชน).pdf`, `893-หนังสือส่งตัว-บริษัท วันจีโอเซอร์เวย์ จำกัด.pdf`

## เป้าหมาย

1. **ออกร่างหลายคน**: เลือกประเภท (ขอความอนุเคราะห์ / ส่งตัว) → รายชื่อคนที่พร้อม → จัดกลุ่มตามบริษัท → ใส่เลขต่อกันจากเลขเริ่มต้น → โหลด zip (Word ค่าเริ่มต้น / PDF) → ทุกฉบับติดป้าย "รอลงนาม" พร้อมเลข/วันที่
2. **อัปโหลดฉบับลงนามหลายฉบับ**: วางไฟล์สแกนหลายไฟล์ → ระบบจับคู่กับหนังสือรอลงนามจากเลขหน้าชื่อไฟล์ → ตรวจ → บันทึกครั้งเดียว
3. **แนะนำการตั้งชื่อไฟล์** ทั้งตอนโหลดและตอนอัปโหลด
4. **ไฟล์รายการเลขหนังสือ (Excel)** ติดไปกับ zip — ไว้ลงทะเบียนหนังสือส่ง / เช็กฉบับที่ลงนามกลับมา

## ไม่ทำในงานนี้ (non-goals)

- หนังสือขอนิเทศ (ออกจากหน้าจัดการนิเทศ — จัดกลุ่มตามกลุ่มนิเทศอยู่แล้ว) — ทำทีหลังได้ด้วยแนวเดียวกัน
- **ปรับหน้าตาหนังสือ (PDF/Word) ให้ตรงแบบราชการตามตัวอย่าง** — เป็นงานแยกถัดไป (ผู้ใช้ขอไว้แล้ว) · งานนี้ใช้ตัวสร้าง Word/PDF ที่มีอยู่ — แก้ทีหลังแล้วปุ่มหลายคนได้หน้าตาใหม่ด้วยอัตโนมัติ
- สแกนรวดเดียวเป็นไฟล์ใหญ่แล้วให้ระบบตัดหน้า
- เปลี่ยนขั้นตอนหนังสือรายคนเดิม (หน้าต่างออกหนังสือทีละคน/หนังสือรวมเดิมยังใช้ได้เหมือนเดิม)

## ห้ามเกิด (anti-goals)

- **ไฟล์ลงนามผิดคน/ผิดฉบับ** — เลขในชื่อไฟล์ต้องตรงเลขร่างของหนังสือรอลงนามเท่านั้น ไม่เดา · จับคู่ไม่ได้ = ให้เจ้าหน้าที่เลือกเอง
- **เลขหนังสือซ้ำ** กับหนังสือที่ออกแล้วหรือร่างที่รออยู่ (ใช้กติกาเดียวกับระบบตอนนี้ — `assertDocNumberFree` + `DocNumberLock`)
- **ติดป้ายรอลงนามครึ่งชุด** — ถ้ามีเลขชนแม้ฉบับเดียว ต้องไม่ติดป้ายฉบับไหนเลย (ทั้งชุดในทรานแซกชันเดียว) และไม่ให้โหลด
- นักศึกษาที่ไม่อยู่ในขั้นที่ออกหนังสือนั้นได้ หลุดเข้าไปในชุด

## ส่วนที่ 1 — ออกร่างหลายคน

**ที่อยู่**: ปุ่มใหม่ในแถบเครื่องมือหน้า T000 (เฉพาะเจ้าหน้าที่) ข้างปุ่ม "ออกหนังสือรวมหลายคน" / "ดาวน์โหลดหนังสือ (zip)" → หน้าต่าง

**ขั้นตอนในหน้าต่าง**
1. **ประเภท**: ขอความอนุเคราะห์ / ส่งตัว
2. **รายชื่อที่พร้อม** (ตามรอบ + ตัวกรองหลักสูตรที่หน้าเลือกอยู่):
   - ขอความอนุเคราะห์: สถานะ `DOCS_APPROVED` และยังไม่มีหนังสือ (`reqLetterUrl` ว่าง)
   - ส่งตัว: สถานะ `ACCEPTANCE_CHECKED` และยังไม่มีหนังสือ (`placeLetterUrl` ว่าง)
   - คนที่ติดป้ายรอลงนามประเภทนี้อยู่แล้ว: ไม่ติ๊กไว้ก่อน แสดงว่า "รอลงนามอยู่ (เลข …)" — ติ๊กได้ถ้าต้องการออกร่างใหม่ (ได้เลขใหม่ แทนร่างเดิม)
   - ข้อมูลไม่พอสร้างหนังสือ (ไม่มีบริษัท · ไม่มีวันเริ่ม/สิ้นสุดฝึก — กติกาเดียวกับหน้าต่างรายคน) → แสดงเหตุผล ติ๊กไม่ได้
   - ค่าเริ่มต้น: ติ๊กทุกคนที่ใช้ได้
3. **จัดกลุ่มตามบริษัท** (`companyId`): บริษัทเดียวกัน = หนังสือรวม 1 ฉบับ · มีปุ่ม "แยกฉบับ" รายคน (คนนั้นได้ฉบับของตัวเอง) และ "รวมกลับ"
4. **เลขเริ่มต้น + วันที่**: กรอกเลขเต็ม (เช่น `660301.26.6.2/1234` — ตัด "ที่ อว" ออกแบบเดียวกับ `normalizeDocNumber`) · ระบบไล่เลขท้าย `/` ต่อกันทีละฉบับตามลำดับในตาราง · แก้เลขรายฉบับได้ · วันที่เดียวทั้งชุด
   - ตรวจซ้ำทันทีก่อนโหลด (กับหนังสือที่ออกแล้ว + ร่างที่รออยู่ + ภายในชุดเอง) — แถวที่ซ้ำขึ้นแดง โหลดไม่ได้จนกว่าจะแก้
5. **รูปแบบไฟล์**: **Word (.doc) — ค่าเริ่มต้น** / PDF — ผู้ใช้ไม่อยากได้ไฟล์ย่อยเยอะ (ต้องไปรวมเอง) → **ต่อฉบับให้น้อยไฟล์ที่สุด**
   - **Word, ขอความอนุเคราะห์ = ฉบับละ 2 ไฟล์**: หนังสือ `.doc` (ตัวสร้างเดิม `buildDispatchLetterHtml` + `createWordBlob` — แก้ได้) + **เอกสารแนบรวมเป็น PDF ไฟล์เดียว** เรียงตามลำดับพิมพ์: รายละเอียดโครงการ → เอกสารของนักศึกษา (ลำดับเดียวกับร่าง PDF รายคน · หนังสือรวม = ของทุกคนในฉบับ) → แบบฟอร์มตอบรับ — เหมือนหน้า 2–13 ของตัวอย่าง 811 (ฉบับลงนามที่สแกนกลับมาเป็นทั้งชุด) · ใช้ตัวรวม PDF เดียวกับ `createDispatchPDF` แต่ไม่มีหน้าหนังสือ
   - **PDF, ขอความอนุเคราะห์ = ฉบับละ 1 ไฟล์**: หนังสือ + เอกสารแนบทั้งชุด แบบเดียวกับร่าง PDF รายคน
   - **ส่งตัว = ฉบับละ 1 ไฟล์** ทั้ง Word และ PDF (ไม่มีเอกสารแนบ)
   - ขนาดโดยประมาณ (ข้อมูลในเครื่อง): เอกสารแนบต่อฉบับ ~8 MB (รายละเอียดโครงการ 4.8 MB + แบบฟอร์มตอบรับ 0.7 MB + เอกสารนักศึกษาค่ากลาง 2.3 MB สูงสุด 81 MB) → 40 ฉบับ ~300 MB+ · สร้างทีละฉบับ แสดงความคืบหน้า "กำลังสร้าง x / n" · เตือนเมื่อชุดใหญ่
6. **โหลด** → zip เดียว ชื่อไฟล์ **`<เลขท้าย>-<ประเภท>-<ชื่อบริษัท>.<doc|pdf>`** และ **`<เลขท้าย>-<ประเภท>-<ชื่อบริษัท>-เอกสารแนบ.pdf`** (ไฟล์ของฉบับเดียวกันเรียงติดกัน · ตัดอักขระที่ใช้ในชื่อไฟล์ไม่ได้) เช่น `1234-หนังสือขอความอนุเคราะห์-บริษัท เอไอเอส จำกัด.doc`
   - ใน zip มี **`_รายการเลขหนังสือ.xlsx`** ด้วย (ผู้ใช้ขอ) — แถวละฉบับ: เลขที่เต็ม · วันที่ · ประเภท · เรียน (ผู้รับ) · บริษัท · นักศึกษา (รหัส + ชื่อ ทุกคนในฉบับ) · ชื่อไฟล์ในชุด — ไว้ลงทะเบียนหนังสือส่งของสารบรรณ / เช็กว่าฉบับไหนลงนามกลับมาแล้ว / ดูตอนตั้งชื่อไฟล์สแกน (ใช้ไลบรารี `xlsx` ที่หน้าเว็บมีอยู่แล้ว)
7. **ติดป้ายรอลงนาม** ทุกฉบับ (เลข + วันที่) **ก่อน**เริ่มโหลด ในคำขอเดียว ทั้งชุดหรือไม่เลย — ชนเลข = ไม่ติดเลย บอกว่าฉบับไหนชน
8. ข้อความแนะนำในหน้าต่าง: ไฟล์ตั้งชื่อขึ้นต้นด้วยเลขหนังสือแล้ว — สแกนฉบับลงนามแล้ว**ตั้งชื่อขึ้นต้นด้วยเลขหนังสือเหมือนเดิม** ระบบจะจับคู่ให้ตอนอัปโหลด

**backend ใหม่**: ติดป้ายรอลงนามหลายฉบับในทรานแซกชันเดียว (ใช้ `DOC_NUMBER_TX` + `assertDocNumberFree` ต่อฉบับ + ตรวจขั้นสถานะต่อคนแบบ `markLetterPending`) — รับรายการ `{ studentIds: [...], docNumber }` + `docDate` + `letter` · เจ้าหน้าที่เท่านั้น · ลงบันทึกการใช้งาน (ชื่อการกระทำภาษาไทย)

## ส่วนที่ 2 — อัปโหลดฉบับลงนามหลายฉบับ

**ที่อยู่**: ปุ่มใหม่ในแถบเครื่องมือหน้า T000 (เฉพาะเจ้าหน้าที่) → หน้าต่าง

1. **ประเภท**: ขอความอนุเคราะห์ / ส่งตัว
2. **รายการหนังสือรอลงนาม** ของประเภทนั้น (ทุกรอบ หรือรอบที่เลือก) — แถวละฉบับ: เลข · วันที่ · บริษัท · รายชื่อนักศึกษา (หนังสือรวม = ทุกคนที่มีเลขร่างเดียวกัน)
3. **วางไฟล์หลายไฟล์** (ลากมาวาง / เลือกไฟล์) — PDF/รูป ตามกติกาไฟล์เดิม
4. **จับคู่จากเลขหน้าชื่อไฟล์**: ตัวเลขที่ขึ้นต้นชื่อไฟล์ = เลขท้าย `/` ของเลขร่าง (เช่น `811-…pdf` → ฉบับที่เลขร่างลงท้าย `/811`)
   - จับได้ฉบับเดียว → ผูกให้ · ไม่มีเลขนำหน้า / ไม่ตรงฉบับไหน / ตรงหลายฉบับ / สองไฟล์ชี้ฉบับเดียวกัน → ไม่ผูก แสดงเหตุผล ให้เลือกฉบับเองจากรายการ
   - กล่องคำแนะนำการตั้งชื่อไฟล์พร้อมตัวอย่างถูก/ผิด
5. **วิธีจัดส่ง** (นักศึกษาดาวน์โหลด / เจ้าหน้าที่จัดส่งให้บริษัท) เลือกครั้งเดียวสำหรับทั้งชุด เปลี่ยนรายฉบับได้
6. **บันทึก** เฉพาะฉบับที่มีไฟล์ — ทีละฉบับผ่าน endpoint เดิม (หนังสือเดี่ยว `PUT /api/admin/t000/review` · หนังสือรวม `PUT /api/admin/t000/letter-batch`) เพื่อให้การตรวจเลข สถานะ แจ้งเตือนนักศึกษา และบันทึกการใช้งานเหมือนออกทีละคนทุกอย่าง · แสดงผลรายฉบับ (สำเร็จ / ไม่สำเร็จ + เหตุผล) · ฉบับที่ไม่สำเร็จคงอยู่ในรายการให้ลองใหม่

## คำอธิบายในหน้าต่าง (ผู้ใช้ขอ)

เจ้าหน้าที่ต้องรู้จากหน้าต่างเองว่าแต่ละขั้นทำอะไร — ภาษาธรรมดา สั้น เป็นข้อ · ส่วนที่ยาวพับเก็บได้ (ไม่บังรายการ)

**หน้าต่างออกร่างหลายคน** — บอกเส้นทางทั้งหมดตั้งแต่ต้นจนจบ:
1. เลือกประเภท → ตรวจรายชื่อ (คนบริษัทเดียวกันรวมเป็นฉบับเดียว กด "แยกฉบับ" ได้) → ใส่เลขเริ่มต้นและวันที่ (ระบบไล่เลขต่อให้ แก้รายฉบับได้)
2. กดโหลด = **จองเลขและติดป้าย "รอลงนาม" ให้ทุกฉบับทันที** (เลขชนฉบับเดียว = ไม่จองเลย บอกว่าฉบับไหน) · ยกเลิกป้ายรายคนได้ที่หน้าต่างออกหนังสือเดิม
3. สิ่งที่ได้ใน zip (Word: หนังสือ + เอกสารแนบรวมเล่ม · PDF: ฉบับละไฟล์ · Excel รายการเลขหนังสือ)
4. ต่อจากนี้: แก้ Word ให้ตรงแบบ → พิมพ์หนังสือตามด้วยเอกสารแนบ → เสนอลงนาม → **สแกนทั้งชุดฉบับละไฟล์ ตั้งชื่อขึ้นต้นด้วยเลขหนังสือ** (ชื่อไฟล์ใน zip ใช้ได้เลย) → อัปโหลดด้วยปุ่ม "อัปโหลดฉบับลงนามหลายฉบับ"

**หน้าต่างอัปโหลดฉบับลงนามหลายฉบับ**:
1. วิธีตั้งชื่อไฟล์ให้ระบบจับคู่เอง + ตัวอย่างถูก/ผิด (`811-บริษัท….pdf` ✓ · `660301.26.6.2-811….pdf` ✓ · `scan001.pdf` ✗ ต้องเลือกฉบับเอง)
2. ความหมายของวิธีจัดส่ง (นักศึกษาดาวน์โหลดเอง / เจ้าหน้าที่จัดส่งให้บริษัท)
3. กดบันทึกแล้วเกิดอะไร: หนังสือเข้าระบบ · สถานะนักศึกษาเปลี่ยน · ป้ายรอลงนามหาย · **นักศึกษาได้รับแจ้งเตือน** · ฉบับที่ไม่สำเร็จค้างไว้ให้ลองใหม่

## ข้อกำหนดร่วม

- ใช้ตัวสร้าง Word/PDF ตัวเดียวกับหน้าต่างรายคน (ไม่สร้างแม่แบบหนังสือชุดใหม่)
- หนังสือรวมในงานนี้เท่ากับหนังสือรวมเดิม (เลขเดียวกันทุกคนในฉบับ · `reqLetterBatch`/`placeLetterBatch` ตอนบันทึกฉบับลงนาม)
- ทำงานในธีมสว่าง/มืด และจอแคบได้ (ตามมาตรฐานหน้าอื่น)
- CHANGELOG + เทสต์ backend (endpoint ใหม่: ทั้งชุดหรือไม่เลย · เลขชน · ขั้นสถานะ · สิทธิ์เจ้าหน้าที่) + เทสต์ฟังก์ชันล้วนฝั่งหน้าเว็บ (ไล่เลข · จับคู่ชื่อไฟล์ · ตั้งชื่อไฟล์) + ตรวจในเบราว์เซอร์จริง

## ตัดสินโดยผู้ออกแบบ (ผู้ใช้ยังไม่ได้ยืนยัน — แก้ได้)

- **ลำดับไล่เลข**: เรียงตามชื่อบริษัท แล้วรหัสนักศึกษาคนแรกในฉบับ — ลำดับในตาราง = ลำดับเลข
- **เลขเริ่มต้นต้องลงท้ายด้วยตัวเลขหลัง `/`** (เช่น `/1234`) — ไม่ใช่ตัวเลข = ไล่ให้ไม่ได้ ให้กรอกรายฉบับเอง
- **วันที่เดียวทั้งชุด** (ร่างรอบเดียวกันเสนอลงนามวันเดียวกัน)
- **ชื่อไฟล์ที่จับคู่ได้**: ขึ้นต้นด้วยเลขท้าย (`811-…`, `811 …`, `811.pdf`) หรือขึ้นต้นด้วยเลขเต็ม (`660301.26.6.2-811…`, `660301.26.6.2_811…`) — เทียบกับเลขท้าย `/` ของเลขร่างเท่านั้น
- **ออกร่างใหม่ให้คนที่รอลงนามอยู่** = เลขใหม่แทนเลขร่างเดิม (เลขเดิมว่างให้ใช้ต่อ)

## ให้ผู้สร้างตัดสินเอง

- หน้าตา/ตำแหน่งปุ่มและหน้าต่าง (ตามแบบหน้า T000 ที่มีอยู่)
- ไลบรารีสร้าง zip ฝั่งหน้าเว็บ (ยังไม่มีในโปรเจกต์ — เลือกตัวเล็ก) และการสร้างไฟล์ทีละฉบับเพื่อไม่ให้หน่วยความจำเต็ม
- รูปแบบ request/response ของ endpoint ติดป้ายหลายฉบับ
- จำนวนไฟล์อัปโหลดสูงสุดต่อครั้ง (ให้พอกับหลายสิบฉบับ)
