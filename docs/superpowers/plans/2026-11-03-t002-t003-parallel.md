# T002/T003 คู่ขนาน — แผนลงมือ

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** นักศึกษาช่วงฝึกงานอยู่สถานะหลักเดียว "ส่งเอกสารฝึกสหกิจ" (`INTERNSHIP_STARTED`) · T002 และ T003 ส่ง/ตรวจ/ตีกลับ/ส่งใหม่ แยกกันตามสถานะไฟล์ของแต่ละอัน

**Architecture:** กติกาทั้งหมดอยู่ใน helper คู่ — backend `utils/internshipForms.js` + frontend `src/utils/internshipForms.ts` (สถานะรองคิดจาก `Document` ชนิด `T002_FORM`/`T003_FORM` ล่าสุด) · controller/หน้าจอเรียก helper แทนการเช็คสถานะสหกิจ · สคริปต์ย้ายนักศึกษาสถานะเก่า → `INTERNSHIP_STARTED` · ค่าเก่าใน enum คงไว้และถือเป็นช่วงฝึกงาน

**Tech Stack:** Express + Prisma (MySQL) · Jest (mock prisma `__tests__/__mocks__/prismaClient.js`) · React 19 + TS · Playwright (unit spec + e2e กับ backend จริง)

**Spec:** `docs/superpowers/specs/2026-11-03-t002-t003-parallel-design.md`

## Global Constraints

- ไม่มี migration ของ schema · ไม่ลบค่าใน enum `CoopStatus`
- ค่าเก่า `T002_SUBMITTED` `T002_EDITS_REQUIRED` `T003_SUBMITTED` `T003_EDITS_REQUIRED` `T003_APPROVED` = ช่วงฝึกงาน (เหมือน `INTERNSHIP_STARTED`) ทุกที่ จนกว่าจะรันสคริปต์
- คำที่ผู้ใช้เห็น: สถานะหลัก **"ส่งเอกสารฝึกสหกิจ"** · สถานะรอง **ยังไม่ส่ง / รอตรวจ / ต้องแก้ / ผ่าน** · ผ่านครบ **"เอกสารฝึกสหกิจครบ"**
- API ตรวจคงเส้นทางและ body เดิม: `PUT /api/admin/documents/review-t002|review-t003` และ `/api/teacher/documents/review-t002|review-t003` `{ studentId, status, comment }` — ตีกลับ = `status` ลงท้าย `_EDITS_REQUIRED` (ต้องมี comment ไม่ว่าง) · อนุมัติ = `T002_SUBMITTED` / `T003_APPROVED`
- ตอบภาษาไทย · CHANGELOG ทุกการแก้ · ใช้ `git -C <path>` · commit/push เมื่อผู้ใช้สั่งเท่านั้น

## Review Focus

1. นักศึกษาสถานะเก่า (ยังไม่รันสคริปต์) ต้องส่ง/ถูกตรวจ/นัดนิเทศ/ขึ้นในรายการได้เหมือน `INTERNSHIP_STARTED` → Task 1 (`isInternshipStatus`), Task 3, Task 4 มีเคสค่าเก่า

5. ตัวนับเมนู/จำนวนรอตรวจของรอบนับคนสถานะเก่าที่ไฟล์รอตรวจด้วย → Task 3
